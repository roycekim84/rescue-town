# Astra 첫 구현 지시

아래 내용을 구현 에이전트의 첫 메시지로 사용한다. 이 프롬프트를 저장소에 넣었다고 에이전트가 실행되거나 Unity 프로젝트가 자동 생성되는 것은 아니다.

---

저장소: https://github.com/roycekim84/rescue-town

Rescue Town의 기획 인계가 준비되어 있다. 컨셉을 처음부터 다시 설계하지 말고 실제 구현을 시작하라.

먼저 AGENTS.md, docs/49_SPEC_AUTHORITY_AND_HANDOFF.md, docs/45_TECH_STACK_DECISIONS.md, docs/46_RUNTIME_AND_ASSET_BASELINE.md, docs/47_ASTRA_IMPLEMENTATION_WORKBOOK.md, docs/48_RELEASE_ACCEPTANCE.md, data/implementation_plan.json, docs/50_IMPLEMENTATION_STATUS.md를 읽고 현재 HEAD와 미커밋 변경을 확인하라. 관련 최신 게임 JSON도 직접 읽어라.

최종 목표는 고양이50종/최대50마리·건물13종·시골마을1개·실제 보상형 광고·저장/복귀·마을축제까지 갖춘 완결된 모바일 v1.0이다. 내부 한마리 시험은 개발 순서이며 작은 MVP를 출시하라는 뜻이 아니다. 구현되지 않은 앱·아트·광고를 완성으로 보고하지 말라.

이번 실행은 M0부터 시작한다. Unity6.3 LTS 계열의 실제 설치 환경을 확인하고 정확한 패치/의존성을 고정한 뒤 game/RescueTown 프로젝트와 재실행 가능한 Editor 생성·검증·빌드 경로를 만들어라. 같은 프로젝트를 다른 에디터가 사용 중이면 충돌을 피하라. M0 완료 조건을 확인한 후 M1 도메인·저장 핵심으로 이어가라.

기획 데이터의 원본은 루트 data/다. 게임 포함본은 검증된 변환으로 생성하라. home/square 별칭을 정규화하고 primaryCondition을 조건문처럼 해석하지 말라. 초기 지원 총액은5500G(최초1000+추가4500), 최초8마리는 onboarding, 정상 발견은 discovery_rules다. 기존 가격·시간을 임시 코드에 맞춰 몰래 바꾸지 말라.

엔진은 Unity, 광고는 공식 Google Mobile Ads/UMP, 저장은 SQLite, 영수증은 최소 SSV Worker/D1를 선정했다. 패키지 호환과 실기기 동작은 아직 검증 전이므로 로그로 확인하라. 테스트에 가짜 광고/가짜 저장을 사용할 수 있으나 release 완료 근거로 사용하지 말라. Unity 테스트와 기존 Python 참고 테스트를 구분하라.

외부 로그인·라이선스·서명·실광고ID·서버 배포·유료 리소스·실기기·아트 생성 권한이 없으면 막힌 항목과 정확한 필요 작업만 기록하고 독립된 코드/검사는 계속하라. 내 인증정보를 추측하거나 공개 Git에 기록하지 말라. 공개 배포나 스토어 제출은 별도 승인 없이 하지 말라.

M0/M1에서는 최종 이미지50마리를 생성하지 말라. 이후 M2에서3마리 시각 표본을 확인한 뒤 M5 생산으로 넘어간다. 가짜 NPC, 수인 캐릭터, 새 지역, IAP, 프레스티지, 희귀도, 실시간 LLM 주민 시스템을 추가하지 말라.

각 실행은 문서 요약으로 끝내지 말고 실제 구현·컴파일·테스트를 진행하라. 실패하면 수정 후 재실행하라. 단계별 상태와 증거를50번 문서와 implementation_plan에 갱신하고 작은 커밋으로 남겨라. 종료 보고에는 변경 파일/커밋/실제 실행 명령/검사 성공·실패·스킵/기기나 빌드 로그/차단 항목/다음 첫 작업을 적어라. 실행하지 않은 결과는 통과로 표기하지 말라.
