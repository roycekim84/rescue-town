# 고양이 50마리 발견 조건 v0.1

상태: **실행 가능한 조건식 작성·구조적 경로 검사 / 엔진·실제 소요시간 검증 전**.
기준 커밋: `42cca6e45a6018f9b6fa43f25cd53dfa2219fc0b`.
고양이 이름·외형·성격·능력치, 센터 정원, 건물 가격, 첫30분 지원금은 변경하지 않는다. 이미지도 생성하지 않는다.

## 1. 데이터 적용 순서
- `data/cats.json`: 50개 Catalog ID, 외형·기본능력·성격의 원본.
- `data/onboarding.json`: 첫8마리 순서·조건·탐색/돌봄시간·초기 지원금의 원본.
- `data/discovery_rules.json`: CAT_001~050의 실행 가능한 발견 조건. 첫8개는 onboarding과 정확히 일치하는 검증용 미러다.
- 기존 `cats.discovery.primaryCondition`은 설명 문자열이다. 임의로 코드 조건을 추측하지 않고 신규 테이블을 catalogId로 조인한다.
- CAT별 최소 센터 레벨은 기존 cats.json과 일치한다. 첫영업·시설·정원·예약 조건은 별도로 적용된다.
- 정상42마리의 탐색/돌봄 시간과 장기 경제는 이번 단계에서 다시 조정하지 않았다. 첫8마리 타이머는 onboarding을 그대로 따른다.

조건 언어는 `all`(모두), `any`(하나 이상), `building_level`, `resident_count`, `resident_owned`, `development`, `flag`다. 미지원 조건과 알 수 없는 ID는 데이터 오류다. 표현식 문자열 eval은 사용하지 않는다.
건물 레벨은 공사 중 목표가 아닌 **완료된 레벨**, 주민 수는 **돌봄 완료 고유 주민 수**다.

## 2. 발견 조건과 추첨을 분리
첫8마리는 초기 안내 순서로 제공한다. 나머지는 첫 실제 영업 완료 후 시작한다.
조건 충족은 고양이 자동 지급이 아니라 **목격·탐색 가능한 상태**를 뜻한다.

1. 도감에서 충족한 조건과 아직 필요한 시설을 확인한다.
2. 발견 가능한 미보유 고양이 중 하나를 다음 탐색 대상으로 무료 선택할 수 있다.
3. 직접 선택하지 않으면 자격을 갖춘 미보유 후보 중 무작위로 선택한다.
4. 탐색 → 짧은 구조 상호작용 → 돌봄 → 정착을 진행한다.

랜덤은 만나는 순서를 바꾸는 장치다. 꽝·중복 고양이·광고 재추첨은 없다.
선택 후 Catalog ID와 예약 Resident ID를 고정하며, 재접속/재시도에서 다른 고양이로 바꾸지 않는다.
마음은 센터10+앞49마리 정착 후 환영 이벤트로 만난다. **축제 완료를 요구하지 않는다.** 조건만 맞았다고 클릭 전에 자동 획득하지도 않는다.

## 3. 밤·비·관계·화면 속 NPC는 필수 수집 조건이 아니다
영구 해금은 센터·시설·발전도·주민 수로 판정한다.
밤이/은하 등은 저녁 분위기를 선호하는 만남으로 표현하되 현실 특정 시각 접속을 요구하지 않는다. 이미 조건을 충족한 신호를 낮이라고 숨기지 않는다.
단비는 센터9 + (광장1 또는 카페3) + 주민35로 만난다. 비 표현이 있으면 처마에서 비를 피하고, 없으면 같은 처마에서 쉬는 장면으로 대체한다. 전역 날씨를 신규 필수 기능으로 만들지 않는다.
아리는 센터8 + 공원3 + 주민30으로 만난다. 친구 관계 수나 우연히 NPC가 같은 화면에 모이는 일을 요구하지 않는다.
연출 참가자는 실제 보유 주민에서 고른다. 적당한 참가자가 없으면 혼자 접근하는 장면으로 대체하며 가짜 소유 주민을 만들지 않는다.
이 규칙은 구 문서의 미확정 '밤에만/비에만/친구 몇 쌍' 예시보다 우선한다.

## 4. 정원·구조 진행·복귀
- 한 번에 구조 작업1개. 선택 시 빈 정원1칸을 예약한다.
- 사용 정원 = 정착 주민 + 예약/돌봄 중 고유 작업의 고양이. 동일 작업을 예약과 돌봄으로 중복 집계하지 않는다.
- 정원이 가득 차면 다음 탐색 시작을 보류하고 센터 확장 목표를 안내한다. 위험한 고양이를 보여주고 방출/광고를 요구하지 않는다.
- 상태: `search_reserved → scene_ready → care_pending → settled`.
- 탐색 결과·구조 장면·돌봄 결과는 비접속이나 시간대 변화로 사라지지 않는다.
- 닫기/재실행은 취소나 재추첨이 아닌 동일 작업 재개다. 비접속 중 다음 고양이를 무한 자동 수령하지 않는다.
- 정착 시 예약 제거·Resident 생성·도감 기록은 하나의 영속 트랜잭션으로 적용한다. 중복 완료 이벤트로51번째 주민이 생기면 안 된다.
- 참고 Python reducer 검사는 실제 기기 강제종료·파일 쓰기 원자성 검증이 아니다.

## 5. 힌트와 버튼
기본 힌트는 캐릭터성을 살린 문장, 상세 조건은 동일 eligibility 트리에서 생성한다.
예: 오레오 → `센터9 완료 / 첫영업 완료 / 빵집1 필요`.
조건 충족: `탐색 대상으로 선택`. 정원 부족: `센터 확장`. 이미 예약됨: `진행 중 구조로 이동`.
any 조건은 두 건물이 모두 필요한 것으로 표시하지 않는다. 표시 이름은 기존 localizationKey와 플레이어 이름을 사용한다.

## 7. 제작 범위
기존 구조 패턴을 재사용한다. 장소ID는 시골마을 안의 논리적 지점이며50개의 새 배경이나 새 지역을 뜻하지 않는다.
scenery 농로·빈집은 농장·주택 건물 조건과 별개다. 필요한 실제 시설은 조건식으로만 판단한다.
발견 조건은 이제 실행 가능하지만 실제 아트/장면/이동/힌트 UI는 구현 전이다.
다음은 이번 조건과 첫30분 분할 지원금을 장기 경제 모형에 통합하고 정상 탐색/돌봄 시간 및 접속 패턴을 다시 검증한다. 이전 완주 일수를 새 정책의 결과로 재사용하지 않는다.
