# 광고 보상 트랜잭션 v0.1

상태: SDK/서버 미구현, 보상 계약과 참조모형 단계. 엔진은 아직 선택하지 않는다.
기본 배율·10분단축·작업당3회·8시간·초기 광고자격은 기존 JSON을 유지한다.

## 1. 닫힘과 보상 자격은 다르다
Google 공식 Unity 가이드의 Show 보상 콜백은 전체화면 닫힘/노출/클릭/OnAdPaid 이벤트와 별도로 정의돼 있다.
https://developers.google.com/admob/unity/rewarded (확인 2026-09-21)

**재생30초/광고닫힘/개발사 광고수익 기록만으로 플레이어 보상을 주지 않는다.**
SDK의 earned callback 또는 검증된 서버 영수증을 보상 근거로 사용한다. 미디에이션별 callback 순서를 고정 가정하지 않는다.
닫힘은 게임 복귀 처리일 뿐, 늦게 도착한 정상 보상 근거를 버리지 않는다. 재생 길이로 성공을 추측하지 않는다.

## 2. 보상 제안과 시청 시도를 분리
광고를 열기 전에 saveId, offerId, rewardGrantId, 대상 Job/Settlement ID, 약속한 보상량/대체보상/버전을 저장한다.
저장 실패하면 Show를 호출하지 않는다. 준비된 광고가 없으면 다시 시도 안내, 게임은 진행 가능.
하나의 보상 제안에 여러 시청시도가 생길 수 있으나 각 attemptId가 서로 다른 것이지 보상을 여러 번 받는 것은 아니다.
한 번의 보상 제안에 대해 미해결 시도가 있으면 새 시청을 강요하지 않는다. 같은 제안의 확정 실패 후 재시도는 동일 보상키를 쓴다.
한 번에 광고 한 개. 빠른 연속 탭으로 두 번 재생하지 않는다. 재시도는 같은 immutable offer를 사용한다.

- 복귀추가 키: saveId+settlementId+offline_extra.
- 시간단축 키: saveId+jobId+성공단축차수(1~3).
- 부스트 키: saveId+확정 topup 번호.

SDK와 SSV가 같은 시청을 확인해도 동일 rewardGrantId를 소비한다. 지급과 지급기록은 단일 커밋이다.
앱에서 보내는 reward amount나 임의 target 변경을 신뢰하지 않는다. 저장된 offer만 적용한다.

## 3. 정상·실패·중단
| 상황 | 처리 |
|---|---|
| 로드실패/네트워크 없음 | 보너스0, 기본 보상/진행 유지, 무한 자동 재요청 금지 |
| 전체화면 닫힘만 옴 | 게임 복귀. 지급 근거가 없으면 아직 미지급 |
| earned callback 수신 | 원장에 한 번 반영. 닫힘보다 늦어도 가능 |
| 중복 earned 또는 늦은 검증 | 이미 같은 지급키가 있으면 추가지급0 |
| 커밋 후 성공알림 전 종료 | 재시작 시 지급기록 확인. 재시청을 요구하지 않음 |
| 지급 증거 자체를 받기 전 프로세스 소멸 | unresolved로 보존. 검증된 서버 영수증 재조회 가능 시 복구. 증거 없이 임의 지급하지 않음 |
| 오래된/다른saveId 보상 | 현재 마을에 붙이지 않음. 원래 계보·시도와 대조 |

실패가 의심된다고 시청을 다시 요구하는 팝업을 강제로 띄우지 않는다. 기존 시청의 증거가 확인되면 새 광고 없이 복구한다.
다만 **SDK가 보상 증거를 주기 전에 앱이 종료된 모든 경우를 로컬만으로 복구할 수 있다고 약속하지 않는다.**

## 4. 서버 검증·복구안
광고 시청 중 강제종료 복구를 보강하는 v1 제안은 **클라이언트 즉시 지급 + 최소 SSV 영수증 확인/조회 서버**다.
이 서버는 전체 마을을 매초 저장하는 서버가 아니고, 클라우드 저장도 아니다. 이번에 서버를 배포한 것은 아니다.
Google SSV는 signature와 고유 transaction_id를 제공하며 지연될 수 있다. 공식 설명: https://developers.google.com/admob/android/ssv

실제 구현 시 서버 발급 불투명 attempt token을 custom_data로 연결한다. 고양이 이름/이메일/자유입력/앱 비밀키는 넣지 않는다.
서버는 공식 키/서명, ad unit, 네트워크, 시각, 이미 등록된 시도/보상제안 및 고유 transaction_id를 검증한다.
중복 콜백은 같은 영수증을 반환하고, 앱도 동일 지급키로 다시 검증한다. 단순히 source='verified_ssv'라는 문자열만 보고 신뢰하면 안 된다.
미디에이션 소스별 SSV/콜백 지원, 익명 설치인증·보관기한·삭제/개인정보·동의는 SDK 선택 시 명세하고 시험한다.
SSV 도달/지원이 없는 경우와 로컬 원장 전체 손실은 복구 한계로 남는다. 이를 숨기거나 임의 성공률을 약속하지 않는다.

## 5. 시간단축 대상이 먼저 끝나는 경합 — 신규 상세안
광고를 볼 때는 공사가 남아 있었지만 긴 앱 중단 후 증거가 도착하면 이미 완료됐을 수 있다.
다음 공사에 몰래10분을 적용하거나 '광고 봤지만0보상'으로 끝내지 않는다.
제안 시 `q=min(600,남은초)`와 당시 **부스트·지원금 제외 정상 영업 G/분**을 저장한다.
수신 시 남은 작업에 먼저 `min(q,현재 남은초)`를 적용한다. 못 쓴 약속시간은 미리 고지한 영업기준 골드로 지급한다.
`대체G = 미사용 약속초/60 × 제안시 정상 영업 G/분`.
새 티켓/프리미엄 재화를 만들지 않는다. 숙련/능력경험을 주지 않고, 한 지급키는 한 번만 처리한다.
제안 문구 예: '최대10분 단축. 작업이 먼저 끝난 부분은 표시된 기준으로 골드 보상.'
정상 영업수입이0이거나 보상이 유용하지 않으면 새 제안을 하지 않는 쪽을 런타임에서 확인한다.
이 예외보상은 **이번 신규 상세 초안**이며 기존 장기 시뮬레이션에 포함되지 않았다. 실제 발생률과 밸런스는 추가 확인한다.

## 6. 부스트·광고자격
부스트는 약속한10분 전체가30분 상한에 들어갈 때만 제안한다. 시청 중 소비하지 않고 게임 복귀 후부터 사용한다.
동시에 하나의 미해결 부스트 제안만 두며, 늦은 증거를 기다리는 동안 같은 공간을 중복 판매하지 않는다.
초기에는 첫실제영업 AND 실제 플레이20분 AND 동의 어댑터의 광고 요청 가능 상태를 모두 확인한다.
제안을 보여주는 것과 동의를 확보한 것은 다르다. 추적 동의를 거부했다고 핵심 게임/기본보상을 차단하지 않는다. SDK별 요청 가능 경로는 별도 규정·문서 검토 대상이다.
개발·QA는 공식 테스트 광고/테스트기기를 사용한다. 이번 테스트는 실제 광고를 호출하지 않는다.

## 7. 화면 문구
- 기본 정산: '고양이들이 12,480G를 벌었어요. 기본 수익은 받았어요.'
- 선택 보상: '[광고 보고 +12,480G] [마을로]'. 이미 기본을 받았는데 다시총액을 주는 버튼처럼 표시하지 않는다.
- 확인 대기: '추가 보상을 확인 중이에요. 마을은 계속 이용할 수 있어요.'
- 저장 실패: '진행 저장을 마치지 못했어요. 다시 시도해주세요.' 완료됐다고 거짓 표시하지 않는다.

## 8. 반드시 남는 출시 시험
실제 SDK 테스트 광고에서 earned/closed/failed 순서, 앱 전환, 시청중종료, 네트워크 끊김, SSV지연/중복, 대상완료 경합, 동의 거부, 테스트/실광고ID 분리를 검증한다.
Python 참조모형은 증거가 이미 정규화되었다고 가정하며 SSV 서명/HTTP/API보안/앱스토어 준수 시험이 아니다.
