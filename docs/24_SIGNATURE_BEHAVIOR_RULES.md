# Signature Behavior Rules — v1.0

## Purpose
Each of the 50 residents should remain recognizable not only by appearance but by repeated habits.

## Rule
Signature Behavior is not a unique expensive animation for every cat. It should normally be implemented using:
- existing common actions
- facility preference weights
- behavior probability modifiers
- contextual variants
- occasional small bespoke timing/pose variation

## Examples
- 먹보: food-facility sniff action weighted higher.
- 느긋함: sunny/soft rest point selection weighted higher.
- 수줍음: crowded locations choose edge points.
- 사교적: approach lone or grouped residents more often.
- 장난꾸러기: boxes/toys/props selected more often.
- 영리함: inspect machines/interactive objects more often.
- 활발함: longer routes/run bursts.
- 다정함: rest or socialize near another resident.

## Design Goal
A player who watches a resident repeatedly should be able to say things like “호두 또 빵집 앞에 있네” without opening a stat screen.

## Balance
Signature behaviors should primarily create identity and observation value. They must not become large hidden economic advantages.

## Cross-character Rescue Events
Some rescue events may include previously rescued residents as narrative participants. This helps later discoveries feel connected to the player's existing village history.

Do not create fragile chains where missing one optional event permanently blocks another cat. Required participants should already be naturally obtainable earlier in progression or have fallback conditions.
