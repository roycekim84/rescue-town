# 런타임·마을·아트 구현 기본값 v0.1

상태: 구현이 멈추지 않도록 정한 작업 기본값. 시골마을·50마리·직원3 원칙은 고정하고 아래 시각 크기·필지 좌표는 플레이 검증으로 조정 가능하다. 이 문서는 실제 이미지/게임을 생성한 결과가 아니다.

## 1. 프로젝트와 데이터 흐름
`game/RescueTown/`를 Unity 루트로 사용한다. 기존 data/docs/tools/reports를 이동·삭제하지 않는다.

```text
game/RescueTown/Assets/RescueTown/
  Domain/             # 순수 C# 상태, 조건식, 경제, 성장, 명령
  Application/        # 단일 명령 처리, 정산/화면 흐름
  Infrastructure/     # SQLite, 시계, 광고, 영수증, 분석
  Presentation/       # 고양이/건물/카메라/UI
  Editor/             # 콘텐츠 검증, 재현 가능한 씬/프리팹 생성, 빌드
  Tests/EditMode/
  Tests/PlayMode/
```

금액·숙련·배치·발견 자격은 Domain이 소유한다. Presentation은 조회와 명령 전송만 한다. ScriptableObject는 에디터 표현 캐시로 쓰되 저장소 JSON과 별도의 진실을 만들지 않는다.
핵심 엔티티는 CatDefinition, ResidentInstance, BuildingDefinition, BuildingInstance, RescueJob, ConstructionJob, CraftJob, SaveState, SettlementReceipt, RewardOffer/Attempt다. Clock/Random/Store/Ads/Receipt/Analytics는 인터페이스 경계로 둔다. 초기에는 수동 의존성 조립으로 충분하고 DI 프레임워크·ECS·실시간 LLM은 필수로 추가하지 않는다.

## 2. 패키징과 정규화
data/cats, buildings, progression, development_score, economy_balance, onboarding, discovery_rules, rescue_timing, persistence_contract를 읽고 관계를 검증한다. implementation_plan은 빌드/작업 메타데이터이며 플레이 데이터가 아니다.
허용 목록의 게임 JSON과 콘텐츠 manifest만 StreamingAssets/GameData로 복사한다. 플랫폼별 읽기 어댑터를 사용하고 Android 패키지 내부를 일반 파일 경로라고 가정하지 않는다. 원본 SHA-256 목록을 생성해 Editor/기기 데이터 일치를 검사한다.
- home → housing, square → town_square는 선호시설의 명시적 별칭만 정규화한다. 미등록ID는 오류이지 랜덤 대체가 아니다.
- cats의 primaryCondition은 설명이며 실제 조건은 discovery_rules다.
- 첫8개 조건은 onboarding과 대조한다. 두 파일을 따로 해석해 서로 다른 주민을 만들지 않는다.
- 조건식은 all/any와 등록된 leaf를 파싱한다. 문자열 eval/동적 코드 실행은 금지한다.
- 기존 필드명(unlock/staff/primary 등)은 명시적 DTO 변환에서 처리하며 비슷한 새 이름을 추측하지 않는다.

## 3. 마을 배치 기본값
한 개의 고정 지도와 지정 필지를 사용한다. 작업 시작안은36×36 논리 격자, 2:1 다이아몬드 투영이다. 경로 그래프와 좌표는 별도 village_layout 데이터로 M3에서 확정한다. 카메라 회전/지역 이동/도로 편집은 없다.
주택 외12개 건물은 각각 한 채. 주택 필지는 최대13곳이다. 따라서 최대 완공 건물은25채이며 '건물13종'과 혼동하지 않는다.
주택 Lv1~5 거주 정원은2/2/3/3/4. 13채×4=52개의 침상으로50마리 모두 집을 갖게 할 수 있다. 구조 상한은 여전히 센터 최대50이며 집이 없으면 임시 숙소다.
센터3~10의 주택 필지 공개 수는2/3/5/6/8/10/11/13을 시작안으로 한다. 반복 주택은 동일 건설·업그레이드 비용을 따르되 발전도는 종류별 최고 완료레벨만 집계한다. 주택 정원/반복 비용을 기존 시뮬레이션이 계산했다고 주장하지 않는다.
구조센터는 중심 필지, 생산시설은 외곽, 공원/광장은 중앙 동선, 주택은 주변에 배치한다. 첫30분 허용구매 제한은 그대로다. 모든 입구·작업점·좌석은 연결된 경로/예약 슬롯을 갖는다. 필지 좌표 검사는 수동배치 후에도 실행한다.

## 4. 주민 생활과 경제
50마리 모두 데이터상 존재한다. 일반 뷰는 필요한 실제 ResidentView만 생성하고 프로필/따라가기 대상은 우선 유지한다.
야외 최대16마리 표현을 최초 성능실험 값으로 둔다. 건물 확대에서는 배치 직원최대3+실제 보유 손님을 예약한다. 같은 Resident ID를 실내와 야외에 동시에 복제하지 않는다.
화면 인구가 부족하면 배치 주민의 산책/배달/휴식을 연출하되 정식 배치는 유지한다. 초반 고양이가1마리면 인구목표를 맞추려고2마리로 복제하지 않는다.
A* 경로/WorkPoint 예약을 쓰고 막힌 길·예약 해제·시설 업그레이드 때 복귀를 처리한다. 물리 RigidBody로 마을을 정밀 시뮬레이션하지 않는다.
고양이 선택→작은 카드→프로필/따라가기. 건물 선택→지붕/앞벽 cutaway→관리 sheet. 일시 선택 해제 시 세계 상태를 재생성하지 않는다.

## 5. 아트 생산 계약
50개 고정 Appearance Definition을 작성한 뒤 공통 규격을 적용한다. 먼저 CAT_001,002,003으로 단모/장모/턱시도 차이를 시험한다.
기본은 네 발, 공통2D bone/animation 구조다. 좌우 비대칭 얼굴·털은 SpriteRenderer.flipX만으로 반전시켜 정체성을 바꾸지 않는다. 네 방향(NE/NW/SE/SW)의 외형 레이어나 방향별 스프라이트를 준비하고 뼈 공유는 방향/체형 호환 범위 안에서만 한다.
프로필은 같은 캐릭터 prefab/외형을 전용 카메라로 렌더링하거나 동일 승인 원본에서 파생한다. 별개 생성으로 다른 얼굴이 되면 불합격.
작업 원본 권장 규격은 몸체 기준512px 투명 캔버스, 프로필512px, UI 기준1080×1920이다. 이는 자산 제작 출발값이며 기기별 실제 픽셀/메모리 보장은 아니다. 확대 최대배율과 텍스처 import 규격은 M0/M2에서 측정해 고정한다.
기본 행동 Idle/Walk/Run/Sit/Sleep/Eat/Play/Social/Happy와 업무용 PawPress/Push/Carry/Comfort를 공용 행동 카탈로그로 만든다. 고양이50마리마다 독립 전체 애니메이션을 무제한 생성하지 않는다. 실패 시 품질을 낮추는 대신 방향별 sprite-sheet 방식 대안을 비교하고 같은 정체성 검사를 적용한다.
직업 소품은 overlay. 길찾기/의상/생산을 한 컴포넌트에 섞지 않는다. 일러스트 한 장을 마을 배경으로 깔아 살아 있는 게임처럼 보고하지 않는다.
실제 생성 도구 사용권/원본 파일/사용허가가 없으면 필요한 asset ID·규격·프롬프트만 기록하고 `blocked_external`로 둔다. 도구를 갖고 있다고 추정하거나 파일 경로만 만들어 에셋 완료라고 표시하지 않는다. 라이선스와 생성 출처를 asset manifest에 남긴다.

## 6. 꾸미기·생활 콘텐츠 제작량 기본값
초기 제작 예산은 순수 장식24종(6가족×4변형) + 기능성 설비8종으로 둔다. 이는 기존 미정 수량을 위한 작업값이며 신규 희귀도/가챠를 뜻하지 않는다.
가족은 벤치/쿠션/식물/장난감/상자/벽장식. 호환 슬롯에서만 재사용 가능하다. NPC 상호작용 anchor가 없는 벽장식은 억지 행동을 추가하지 않는다.
기능성 설비는 농장·어시장 공급, 카페·식당·잡화점·미용실·빵집 수익, 공방 작업효율에 각각 최대5% 한 슬롯만 적용한다. 장식에는 수익 우열이 없다. 기본 건물 업그레이드와 설비 부스트를 중복 계상하지 않는다.
레벨5 건물 장식 슬롯은Lv3/Lv5에, 레벨10 건물은Lv3/Lv5/Lv8/Lv10에 열린다. 기능성 슬롯은 해당 건물Lv3+공방 해금 후1개. 공방 이전 잠긴 슬롯은 노출을 최소화한다. 주택/공원/광장은2개 지정 장식점으로 시작한다.
각 설계도 비용/시간은 기존 제작 범주를 참조한다. M3에서 interior_catalog.json을 작성하고 모든 해금 경로/가격/anchor를 검사한 뒤 M5 아트 생산한다. 기획 기본 수량만으로 완성 에셋을 만든 것으로 간주하지 않는다.
생활 micro-event는15개 재사용 패턴을 제작 목표로 둔다. 예: 기지개/햇볕낮잠/벤치휴식/코인사/함께산책/상자놀이/나비구경/꽃냄새/꼬리인사/그루밍/물마시기/간식/창가구경/기계구경/친구옆휴식.

## 7. UI·접근성·오디오
세로/태블릿 중앙 안전 레이아웃, pan/zoom, 터치 우선, back는 단계적으로 닫기. 프로필과 배치목록은 길이50까지 스크롤/가상화한다.
한국어/영어를 시작 언어로 하고 사용자 이름은 별도 자유입력이다. 폰트는 배포권한 있는 원본만 사용하고 한국어·긴 이름·숫자·fallback 글리프를 기기에서 검사한다. 시스템 폰트를 임의 복제하지 않는다.
색만으로 가능/잠금을 구분하지 않는다. 효과음/BGM 볼륨 분리, 햅틱 끄기, 카메라 자동이동/반짝임 최소화 옵션을 둔다.
오디오 범위는 마을 BGM1, 축제 BGM1, 앰비언스1, UI/고양이/시설 효과음군. 최종 아트와 같이 출처를 기록한다.

## 8. 성능은 목표를 측정해 판정
최저 QA 기기에서 안정적인30fps, 지원 가능한 기기에서60fps를 목표로 시작한다. 고양이50 데이터/최대25건물/야외16/실내직원3/프로필·광고복귀를 포함한 최악 장면을 측정한다.
목표 초기 앱 작업집합512MiB, 콜드스타트10초 이내, 저장 커밋 p95 200ms 이내를 경고선으로 둔다. 기기와 SDK로 차이가 크므로 이 수치는 측정 전 SLA가 아니다. 안전한 저장을 위해 성공 UI를 늦춰야 하면 안전을 우선한다.
M0에 기기명·OS·프레임/메모리 예산을 고정하고 M6에서 결과를 남긴다. 성능 문제를 고양이 도감 축소나 가짜 NPC로 해결하지 않는다.
