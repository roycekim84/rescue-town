# 오프라인 정산 계약 v0.1

상태: 엔진 구현 전. 기존 economy_balance/onboarding/rescue_timing을 적용하며 수치 밸런스는 바꾸지 않는다.

## 1. 서로 다른 시간을 분리한다
| 항목 | 비접속 시 처리 |
|---|---|
| 정상 골드·직업숙련·능력 경험 | 한 실제 비접속 구간의 처음8시간까지 |
| 이미 시작한 건설·센터 공사·탐색 | 실제 경과시간 전체. 8시간 뒤에도 완료될 수 있음 |
| 시작한 돌봄 | care 시작 시 저장한 작업량/속도로 실제 경과시간 처리 |
| 공방 제작 | 직원이 있을 때 유효작업시간. 이번 명세는 수익/성장과 같은8시간 창을 사용 |
| 구조 현장 조작·정착 확인 | 접속 후 진행. 미접속 중 새 구조 자동 연쇄 없음 |
| 수익×2 남은 시간 | 실제 foreground gameplay에서만 감소. 백그라운드/광고 시청 제외 |
| 게임 내 아침/밤 | 생활 연출. 실제 골드/공사 시간 기준으로 사용하지 않음 |

앱이 광고 전체화면을 보여주는 동안 정상 수익·기존 타이머는 실시간 진행시키되 부스트/튜토리얼 플레이 카운터는 멈춘다.
광고 때문에 생긴 pause/resume만으로 새 오프라인 보상 팝업을 발행하지 않는다. 앱이 실제 종료됐다면 마지막 내구성 체크포인트부터 한 번만 복귀 정산한다.

## 2. 단일 복귀 정산
백그라운드로 이동할 때 absenceId와 마지막 반영 시점/시계 기준을 저장한다.
복귀 처리기는 입력을 잠깐 막고, 동일 absenceId에 대해 저장된 상태에서 정산 계획을 만든다.
수익/성장/공사완료/지원금 사실/커서/영수증을 하나의 커밋으로 반영하고 그 뒤 UI를 연다.
처리를 여러 체크포인트로 나눌 때도 같은 absenceId와 사용한8시간 예산을 유지한다. 팝업/재시작/배치별로8시간을 새로 주지 않는다.
중복 resume가 와도 완료한 absenceId는 다시 지급하지 않는다. 다음 실제 비접속은 새 ID다.

기본 보상은 먼저 자동 확정한다. UI의 [확인]은 이미 지급된 내용 닫기이며 [광고 추가]만 별도다.
광고 실패/팝업 닫기/자격 없음 때문에 기본 골드를 잃지 않는다.
settlementId는 saveId+absenceId에 연결한다. from/to, 유효초, 기본 골드, 정산당시 광고자격, 밸런스버전을 고정한다.
추가 보상의 기준액은 그 영수증이며, 나중에 건물/직원을 바꿨다고 다시 계산하지 않는다.

## 3. 공사 중 레벨 변화를 반영한다
시간을 한꺼번에 '복귀시 분당수익×시간'으로 계산하지 않는다.
예: 시작100G/분, 2시간 후 공사완료로150G/분, 총6시간 비접속이라면
`100×120 + 150×240 = 48,000G`다. 실제 경제가 이 경계에서 그 수익으로 바뀐다는 테스트용 예시다.
12시간 동안100G/분이었다면 수익은8시간분48,000G. 9시간째 공사가 끝났다면 건물은 완료되지만9~12시간 수입은 주지 않는다.
건물 완료/성장으로 수익률이 바뀌는 구간을 나누고 소수 잔량을 보존한다. 새 건물이 완공되어도 직원0이면 수입0, 기존 업그레이드 중에는 이전 완료레벨과 배치가 유지된다.
과거8시간 사이에 현재 배치한 직원을 소급해 일시킨 것으로 계산하지 않는다.

## 4. 시계 이상
실행 중 경과는 가능한 플랫폼의 단조 시계를 사용하고, 재부팅·프로세스 교체는 저장한UTC/시계 기준과 대조한다. sleep 포함 여부를 플랫폼별로 시험한다.
벽시계가 뒤로 가면 음수 수익을 차감하지 않고 그 구간0초로 처리한다. 남은 작업량은 보존하고 벽시계 기준을 재설정하여 미래 시각에 영원히 갇히지 않도록 한다.
앞으로 큰 점프는 진단 기록과8시간 수익 상한으로 다룬다. 정상 장기 미접속과 기기시계 조작을 로컬만으로 완전히 구분할 수 없다.
기존 공사/탐색의 실제시간 규칙은 유지하되 이상 시계로 단축 가능하다는 한계를 숨기지 않는다. 실제 위변조 방지가 필요하면 검증된 서버시간 계약이 추가로 필요하다.

## 5. 고양이와 화면 복원
현장 확인 전 종료: 같은 고양이/같은 장소/같은 단계로 재개.
돌봄 완료 후 종료: 결과를 보존하고 정착 확인까지 같은 정원1칸을 사용.
화면에50개 스프라이트를 복원할 필요는 없다.50개 데이터/관계를 복원하고 필요한 실제 주민만 표시한다.
직원 산책·생활 연출은 경제나 숙련을 취소하지 않는다. 복귀 시 생활 장면은 현재 유효 상태로 재구성해도 된다.

## 6. 광고와 중복시간
광고 추가는 기본 영수증의+100% 한 번. 영업×2를 오프라인 계산에 적용한 뒤 추가×2로 다시 늘리지 않는다.
5분 미만 비접속에는 기존 데이터대로 추가 제안을 하지 않으며 기본수익은 그대로다.
초기 자격 전 정산의 광고 제안을 나중에 쌓아 보여주지 않는다. 이미 시청을 시작한 제안은43번의 보상 복구 규칙을 따른다.

이번 테스트의 구간 적분은 주어진 수익률을 계산한 정확 산술이다. 실제50마리 성장·공사·지원금이 동시에 바뀌는 전체 엔진 정산기를 구현한 것은 아니다.
