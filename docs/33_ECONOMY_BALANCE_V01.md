# 경제 수치 초안 v0.1 — 출시 밸런스 미확정

상태: **기획용 수치 입력 및 정적 검증 완료 / 실기기·완주 속도 검증 전**.
컨셉은 바꾸지 않는다. 시골 마을 하나, 고양이 50마리, 직원 최대 3마리, 광고를 포함한 완결된 v1.0 출시가 목표다.
이번 수치의 기준은 `data/economy_balance.json`, 진행 조건은 `data/progression.json`이다.
기존 대화·문서의 예시 금액/시간/발전도와 충돌하면 이 문서와 해당 JSON을 우선한다.

## 1. 골드의 의미와 초반 막힘 방지
골드는 개별 고양이 지갑이 아니라 마을 공용 운영비다. 주민 서비스와 생산 활동의 가치를 추상화하여 계산한다.
개별 주민의 잔고·부채·급여를 시뮬레이션하지 않는다.

- 최초 게임 생성 시 1,000G를 한 번 지급한다. 고유 지급 키를 저장해 중복 지급을 막는다.
- 기본 운영 지원금은 실제 1분당 2G. 모든 직원이 미배치여도 유지된다. 광고 부스트는 적용하지 않는다.
- 돌봄, 구조 행동, 주민 이름 변경, 직원 재배치는 골드를 소모하지 않는다.
- 자동 유지비·임금·부채는 없다. 비접속 중 비용으로 파산하지 않는다.
- 구조센터 지원금은 고양이를 팔거나 구조 보상금을 받는 시스템이 아니다.

첫 지원금으로 센터 Lv.2(100G), Lv.3(300G), 첫 주택(200G), 공원(300G)을 마련하고 100G가 남는다.
구조센터 Lv.3 이전에는 외부 정착 UI가 없어도 돌봄을 마친 고양이는 임시 숙소 주민으로 집계한다.
이로써 '정착 해금에는 주민이 필요하지만 주민화가 아직 잠김' 문제도 피한다.

## 2. 건물 수입/비용
아래 분당 수입은 **Lv.1, 기준 효율 100%인 직원 1마리, 추가 보너스 없음** 기준이다.
영업 건물의 직원이 0명이면 해당 건물의 수익은 0이다.

| 건물 | 최초 건설비 | 기준 수입 G/분 | 역할 |
|---|---:|---:|---|
| 구조센터 | 시작 건물 | 0 | 직접 돌봄·자동화·진행 관리 |
| 주택 | 200 | 0 | 거주·생활 |
| 공원 | 300 | 0 | 휴식·관계 |
| 농장 | 1,000 | 4 | 소규모 출하 수익 + 공급 능력 |
| 어시장 | 1,200 | 6 | 판매 + 공급 능력 |
| 카페 | 6,000 | 10 | 판매·교류 |
| 식당 | 18,000 | 14 | 판매·공급 보너스 |
| 잡화점 | 12,000 | 10 | 판매 |
| 공방 | 40,000 | 0 | 제작 시간 단축·꾸미기 해금 |
| 미용실 | 60,000 | 12 | 생활 서비스 판매 |
| 진료소 | 50,000 | 0 | 돌봄·생활 행동 |
| 빵집 | 100,000 | 16 | 판매·공급 보너스 |
| 마을광장 | 90,000 | 0 | 교류·축제 |

공방/진료소에 직원을 배치하는 가치는 제작/돌봄과 해당 분야의 성장이다. 모든 건물을 현금 생산기로 만들지 않는다.
농장의 출하 수익과 공급 점수는 재고 품목의 이중 판매가 아닌 별도 추상 지표다.

### 건물 레벨별 계산
`해당 단계 비용 = ceil(최초 건설비 × 비용계수 / 10) × 10G`
배열의 첫 값은 Lv.1 건설비, 두 번째부터는 그 레벨에 올라갈 때 **추가로 내는 비용**이다. 누적 비용이 아니다.

- Lv.5형 수입/기능 계수: 1 / 1.3 / 1.65 / 2.05 / 2.5
- Lv.5형 비용 계수: 1 / 1.25 / 2 / 3.5 / 6
- Lv.10형 수입/기능 계수: 1 / 1.15 / 1.35 / 1.55 / 1.8 / 2.1 / 2.45 / 2.85 / 3.3 / 3.8
- Lv.10형 비용 계수: 1 / 1.2 / 1.6 / 2.2 / 3.2 / 4.8 / 7.2 / 10.8 / 16.2 / 24.3

0수입 건물에는 수입 계수를 적용해 돈을 생성하지 않는다. 공방 작업 속도와 공급 건물의 공급량에는 같은 기능 계수를 사용할 수 있다.
주택·공원·광장의 생활 행동/슬롯 수는 별도 건물 명세로 정한다.

## 3. 직원 효율과 숙련
`직원 효율 = 0.8 + 0.04 × (주 능력 × 0.7 + 보조 능력 × 0.3) + 직업 숙련 × 0.003`

성격은 기본 능력/행동/선호로 드러난다. 이번 수치 실험에서 성격별 추가 현금 배율은 모두 1이다.
성격에 따른 성장 경향은 후속 밸런스에서 비교하되 특정 성격을 무조건 상위로 만들지 않는다.

직원 기여는 효율순으로 정렬한 뒤 1 / 0.7 / 0.5의 가중치로 더한다.
직원 카드의 UI 순서를 바꿨다고 수익이 달라지면 안 된다.
효율이 모두 100%라면 1마리=1.0배, 2마리=1.7배, 3마리=2.2배다.

`건물 수입 = 기준 수입 × 레벨 계수 × 직원 합산 효율 × 공급 배율 × (1+가구 보너스) × (1+팀워크 보너스)`
가구 보너스와 팀워크 보너스는 각각 최대 5%의 작업 초안이다.
광고 배율은 그 결과의 영업 수입에만 적용하며, 기본 운영 지원금에는 적용하지 않는다.

예: 카페 Lv.3, 친화8/감각4/카페숙련50 직원 1마리라면 효율1.222, 수입16.497G/분이다.
화면에는 16.5G/분으로 보여도 내부 소수 잔량은 유지한다.

### 업무 성장
렌더링 횟수나 손님 애니메이션 완료 횟수가 아니라 **배정된 실제 업무 인정 시간**으로 성장한다.
야외 휴식 연출/밤/화면 밖 상태 때문에 배정된 업무 인정 시간이 끊기지 않는다.
센터의 숙련은 Lv.2 첫 배치부터 쌓이며, 숙련 UI가 늦게 열려도 과거 시간이 사라지지 않는다.

- 능력 경험치: 업무 1분당 1, 주 능력 70% / 보조 30%.
- 능력 n→n+1: `10 × n²` 경험치. 최대20, 만렙 능력의 초과 경험치는 다른 능력에 자동 전환하지 않는다.
- 직업 숙련: 누적 업무 120분→25, 480분→50, 2,160분→75, 10,080분→100. 구간 내 선형 보간.
- 카메라를 닫아도 성장한다. 직장을 바꿔도 기존 숙련과 능력은 남는다.
- 광고로 즉시 완료한 시간은 업무 경험치가 아니다. 골드 ×2가 경험치 ×2가 되지 않는다.

## 4. 공급은 보너스이며 정지 조건이 아니다
농장→식당/빵집, 어시장→식당만 우선 사용한다.
공급이 0이어도 직원이 있는 식당/빵집은 기본 수입을 낸다. 공급이 충분하면 최대15% 보너스.
이 선택은 과거 '공급 부족 시 감점' 예시를 대체한다.

공급량은 생산 시설의 기준 공급량 × 레벨 계수 × 직원 효율.
수요는 소비 시설의 기준 수요 × 레벨 계수 × 직원 효율이며, 광고/가구 보너스는 수요를 늘리지 않는다.
한 농장의 공급을 식당과 빵집 양쪽에 100%씩 중복 배정하지 않는다:
`생산시설 충족률 = min(1, 생산량 / 활성 소비시설 수요 합계)`.
소비시설은 원료별 수요 비중으로 충족률을 평균한다. 개별 재고·운반 실패·품절 대기열은 만들지 않는다.

## 5. 센터 확장 비용·시간
시간은 실제 초이며, 센터 레벨 상승 완료 후 새 상한이 적용된다.

| 목표 센터 Lv | 새 주민 상한 | 비용 | 공사 시간(초) | 요구 발전도 |
|---:|---:|---:|---:|---:|
| 1 | 3 | 시작 | 0 | 0 |
| 2 | 5 | 100G | 0 | 0 |
| 3 | 8 | 300G | 10 | 0 |
| 4 | 12 | 3,000G | 60 | 100 |
| 5 | 17 | 25,000G | 180 | 300 |
| 6 | 23 | 90,000G | 600 | 450 |
| 7 | 30 | 250,000G | 1800 | 650 |
| 8 | 37 | 650,000G | 3600 | 850 |
| 9 | 44 | 1,500,000G | 7200 | 1100 |
| 10 | 50 | 3,200,000G | 10800 | 1400 |

골드 외 주민 수/숙련 조건은 progression.json을 사용한다.
한 주민이 여러 직업 숙련을 갖고 있어도 '숙련 주민 3마리'에서 여러 번 세지 않는다.
이 비용은 '몇 주 걸린다고 검증된 값'이 아닌 첫 수치 초안이다.

## 6. 공사/제작
Lv.5형 단계별 공사 시간(초): 30 / 60 / 180 / 600 / 1,200.
Lv.10형: 30 / 60 / 120 / 300 / 600 / 900 / 1,800 / 2,700 / 3,600 / 5,400.
건물별 동시 작업은 하나, 다른 건물의 공사는 병행 가능하다. 건설 슬롯 판매는 없다.
기존 건물의 업그레이드 중에는 **기존 레벨의 수익·직원 슬롯**을 유지한다. 완료 시점에만 새 값으로 바꾼다.

인테리어 제작 초안: 기본 2,000G/180초, 일반 12,000G/900초, 정성 제작 40,000G/3,600초.
이는 등급/희귀도가 아니라 제작 비용 묶음이다. 공방 작업 한 칸, 직원 없으면 일시정지하되 투자·진척은 보존한다.
제작 작업량은 공방 레벨 계수 × 직원 효율 × 인정 시간으로 감소한다. 완성한 디자인은 재사용한다.
제작 완료 버튼/광고 완료로 경험치를 추가 지급하지 않는다.

## 7. 오프라인·광고
최대8시간, 정상 수익100%를 인정한다. 마지막 경제 정산 이후 최초8시간 구간을 적분한다.
그 구간 안에 공사 완료/숙련 증가가 있으면 시점별로 수입을 나눈다.
건설 타이머는 8시간 상한과 무관하게 실제 경과 시간 전체를 사용한다.
업무 경험의 오프라인 인정 구간은 수익과 같은8시간이다. 음수 경과 시간은0으로 처리한다.

| 광고 지점 | 첫 수치안 | 제한 |
|---|---|---|
| 오프라인 정산 | 기본 정산액 +100% | 정산 ID별1회, 5분 이상 비접속 |
| 공사/제작/탐색 | 남은 시간 최대10분 단축 | 작업 ID별3회, 남은3분 이상에서 제안 |
| 영업 부스트 | 영업 수입×2, 활동 시간10분 | 최대30분 누적, 비접속 중 시간 정지 |

오프라인 기본액에 이미 광고 배율이 들어간 수입을 다시 ×2 하지 않는다.
부스트는 온라인 영업에만, 오프라인 광고는 광고 없는 기본 정산액에만 적용한다.
제작 단축은 현재 작업 속도로 '10분에 해당하는 남은 작업량'을 줄인다. 직원0명으로 제작이 정지된 동안에는 제안하지 않는다.
실제 남은 시간보다 더 큰 단축을 지급하지 않는다. 공사/탐색 광고는 조건·골드·정원 제한을 건너뛰지 못한다.

테스트 예: 정상 수입100G/분이면6시간 기본36,000G, 광고 추가36,000G, 총72,000G.
12시간 비접속은8시간만 인정해 기본48,000G. 별도의 고양이/가구 광고 전용 보상은 없다.

광고 실패/취소/재고 없음은 기본 보상을 없애지 않는다. 지급은 정산/작업/광고 요청 ID로 중복 방지한다.
기본 정산과 추가 보상 상태를 분리 저장하고, 추가 보상 확정 후에는 '기본 받기'가 다시 돈을 주지 않게 한다.
이것은 런타임 구현 요구이며 이번 수학 검증으로 SDK/저장 예외처리가 끝났다는 뜻은 아니다.
전면광고는 이번 기준 시나리오에서는 비활성화한다. 광고 SDK 자체를 생략한다는 의미가 아니다.

## 8. 출시 전 검증
무광고28~35일 / 적당한 광고21~28일 / 적극 활용14~21일은 아직 **목표**다.
가격표와 점수의 산술 검증은 했지만 플레이어 선택, 탐색 조건, 접속 간격을 포함한 완주 시뮬레이션은 하지 않았다.
완주 목표를 맞추려면 건물별 투자 회수시간, 새 기능까지 걸리는 시간, 무광고 재시작 경로를 실제 플레이로 확인한다.
공사·탐색·제작을 전부 동시에 기다려야만 하는 구간, 직업 재배치로 모든 수입이 사라지는 구간을 우선 점검한다.
